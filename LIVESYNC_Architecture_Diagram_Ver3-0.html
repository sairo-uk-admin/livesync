Proposed System Architecture Ver 3.0

LIVESYNC Proposed System Architecture

1.X — Motion Capture & Ingestion

[1.1] Rezzil tracking system

Hawkeye cameras at the venue capture players, ball, officials and other moving entities.Outputs proprietary .exar over WebSocket at 25 fps.

[1.2] WebSocket client

Subscribes to the Rezzil stream.Receives new_game (manifest, once) and frame (every 40 ms).Passes raw .exar into the AWS load balancer.

.exar over WebSocket · 25 fps

2.X — AWS Processing Server · per-match worker pool · incl. delivery [3.1]

[2.8] Custom data processing engine — cross-cutting: underpins all 2.x nodes below

Manages Rezzil .exar data in native format throughout the pipeline before JSON conversion at [2.7].Data reliability: detects and corrects erroneous Rezzil data (limbs deviating due to occlusion errors).Conflict resolution to establish ground truth per entity per frame.Zone-of-influence management - applies tiering logic for [2.6].

[2.1] Load balancer New

Routes each new_game connection to a dedicated per-match worker.Ensures frames stay ordered and local per session.Provisions and retires workers; signals autoscaling when multiple matches run concurrently.

[2.2] Session initialisation Updated

Parse new_game manifest · player IDs · team / kit / pitch / physical attributes.Extracts bone offsets (*_m_pos_*) and scales (*_scl_*) once - not repeated per frame.

[2.3] Entity registry Updated

Rezzil IDs → LIVESYNC IDs.Stores per-player skeleton config from manifest.Drives zone-of-influence tiering and degradation ladder per frame.

[2.4] Frame intake & validation Updated

Validate / drop corrupt frames · deduplicate frameNumbers.Reorder buffer with timeout for out-of-order frames.Gap frequency logged to observability [2.9].

[2.5] Coordinate transform

Pitch metres → Roblox studs.Z-up → Y-up.Pitch scale from new_game.

[2.6] Data compression & payload optimisation New

Per-joint positions removed from per-frame payload (bone lengths fixed on rig; manifest supplies offsets once) - approx. 40% saving.Delta compression: only changed values sent for low-fidelity entities.Zone-of-influence tiering: full quaternion joint data for entities near ball; state-level data (run/walk/idle + root position) for distant entities.Ball routed to separate physics-based interpolation path (see [4.4]).

[2.7] JSON format conversion - final processing step on the server Updated

FrameRate set to 25 (source rate - no server-side upscaling) · Frames array · Joints object with quaternion rotations · Motor6D name mapping (case-sensitive).Bone offsets and scales omitted from per-frame output - manifest-once data.All previous transformations committed in the engine's native .exar form before serialisation to JSON.

[2.9] Observability New

Frame ingestion rate and gap count · per-frame processing latency vs. 50 ms budget · error correction rate (leading indicator of Rezzil degradation) · end-to-end latency via worldClock · worker health per active match.

compact JSON · 25 fps · quaternions

3.X — Delivery Layer · AWS-to-Roblox · direct

[3.1] Direct delivery endpoint Restructured

Processed JSON delivered directly from the AWS worker to Roblox - no intermediate middleware.Photon Realtime removed: wrong topology (single publisher, N read-only consumers; CCU model mismatched against ~200 Roblox shards).Delivery architecture TBD: S3 object, REST endpoint, or WebSocket push.Roblox-side consumption TBD: HttpService polling or MemoryStoreService.Compression and optimisation logic implemented in [2.6] and [2.8] - not in the delivery layer.

direct to Roblox · 3 s client-side buffer

4.X — Roblox Game Server · Server-side Lua

[4.1] Downloader script

HttpService · pcall + RequestAsync fallback to GetAsync · JSONDecode direct to Lua table (bypasses 128 KB StringValue limit).

[4.2] AnimationDataInterface

Stores decoded table · bridges server ([4.1]) → client ([5.1]) · broadcasts AnimationDataReady event.

[4.3] Default rig fallback

Used when a player ID can't be matched (off-tracking, unknown ID, data loss).

[4.4] Ball entity Updated

Position-only path (no joints) via PivotTo() on BasePart.Highest-priority entity: up to 30 m/s, 1+ m between frames.Requires physics-based ballistic interpolation client-side [5.1] - not linear.

RemoteEvent broadcast · per-viewer fan-out

5.X — Roblox Client · Per Viewer · RenderStepped 60 fps

[5.1] RemoteJsonAnimationPlayer Updated

LocalScript · clones RemoteRig · dual accumulators · client-side upscaling 25 → 60 fps using engine-native curves · ballistic interpolation for ball [4.4].60 fps render.

[5.2] Motor6D joint transform Updated

CFrame.new(x,y,z, qX,qY,qZ,qW) · quaternions applied directly - no Euler conversion · written to Motor6D.Transform (no API upload required).

[5.3] PivotTo() movement

World position via MODEL:PivotTo()Y-axis rotation (RootRotY) for facing direction.30 fps movement accumulator.

processed session data persisted from [2.x] worker

6.X — Replay Harness & Durable Session State New

[6.1] Replay harness

Records processed session data from [2.x] worker and replays it through the pipeline at controlled speed.Prerequisite for development and debugging - live feed cannot be paused or reproduced.Also enables fan-facing replay feature (subject to commercial agreement).

[6.2] Durable session state

Persists match metadata, entity manifest, and per-frame position/rotation stream from the AWS worker.Grows a re-renderable match asset library.Storage format, retention policy, and access model TBD.
